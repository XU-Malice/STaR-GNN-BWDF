# Que et al. 六模型复现协议复核（2026-09-05）

## 结论

旧的 82 候选定向队列不适合作为“全部模型已复现论文”的验收程序。新程序先审计
数据与已有预测，再运行固定的 24 组公开参数基准。它不保证数值全部接近；它保证
不把测试表反向调参、训练正常结束或单个总指标接近误称为作者方法的完整复现。

研究对象为 GRU、LSTM、MSNet、MSCMNet_M、MSCMNet_WM、MSCMNet_W。
DMA 是供水分区（A–J），不是第七个算法；每种算法都要报告十个 DMA 和总体。

## 已确认的错误与修复

1. `5b8100b` 把 LSTM A/B/C/D/F/J 的权重衰减从 `0.0001` 改成了 `0`，是错误
   转录。补充文件 S3-2 的 XML 和渲染第 8 页都明确为 `0.0001`，现已恢复。原 87
   任务所用的这些非零值正确，不应因这一错误否定原结果。
2. 原文 Eq.(5) 是未缩放的 QK 点积。新程序明确使用 `none`；历史配置默认
   `sqrt_dim` 只为旧实验兼容保留。FC2 原来没有接收 scaling/update 设置，导致
   同一个命令只改变主干；现统一传播到主干和 FC2 的全部 CAM。
3. 旧队列的 M/W 候选均使用 residual 和 zero-init，WM 候选加 share loss。
   这些不是原文明确给出的校正结构。新基准采用直接拼接/全连接校正，不加上述
   扩展。旧结果不删除，但只作为扩展诊断留存。
4. 旧信号处理只停止显卡监测，不终止训练子进程。新增身份核验停旧工具，新队列
   使用自己创建的训练进程组；中断不再继续下一个候选，也不清理他人的 GPU 进程。
5. 新评分器严格检查完整数组、有限值、十 DMA 次序、起点和首日一致性，禁止靠
   忽略非有限预测获得有限指标。重跑缓存必须与请求、源代码和数据指纹一致。
6. 24 h 直接读取同一次冻结 168 h 递归预测的首日，包括校正中间输出，避免原来
   两次推理 batch 不同产生的浮点细差。未改变标签、预测校准或汇总目标。

## 旧验收存在数学上的不可达区间

在同一组真值上，把全部预测起点拼接后评分（旧代码口径）有恒等式：

`RMSE² = (1 − NSE) × Var(y_true)`。

87 组旧结果的 24 h 总需求真值方差约为 `1585.44214`。以原方案的误差指标相对
差不超过 5%、NSE 绝对差不超过 0.01 为例：

| 模型／24 h | 论文 RMSE | 论文 NSE | 满足 NSE 容差所需的最小 RMSE 相对增幅 |
| --- | ---: | ---: | ---: |
| GRU | 10.194 | 0.916 | 6.25% |
| LSTM | 9.711 | 0.920 | 8.48% |

因此，在旧评分口径与这些真值不变时，无论继续训练多少组，都无法同时通过上述
两个模型的八项总指标门槛。考虑论文三位小数舍入仍不能消除此矛盾。
这不是在证明论文错误：原文说明指标按预测步长计算、测试有 46 个序列，但没有
明确说明序列之间如何汇总。逐序列先求 RMSE/NSE 再平均，不受上述“整体方差”
关系约束；不同评估起点/预处理也会改变真值。必须先核对口径，不能改预测来凑数。

## 一次执行内容

1. 数据审计：核查时间切分和预处理凭据，输出训练/测试 DMA 与气象统计相对
   主文 Table 1/2 的差距、真实预测起点和数据指纹。不自动改变数据。
2. 历史审计：只读取已完成的原始预测，分别重算 `pooled`（旧口径）和
   `origin_mean`（逐预测序列平均，尚未被作者代码证实）。两个口径完整并列报告，
   不能给不同模型/不同指标选择不同口径。此阶段不需 GPU，也不重新训练。
3. 固定 24 组：六模型 × `zscore/minmax` × `Adam/AdamW`，每组仅固定种子
   `20240604`。GRU/LSTM 的十个独立网络仍采用既有确定性 `seed + DMA_index`
   初始化，不做任何种子搜索或五种子重复。训练参数保留 S3 公布的 LR/WD/epoch。
4. 原文结构：M/WM/W 使用 direct、无 zero-init、无额外 share loss；CAM 使用
   Eq.(5) 的 `none`，十 DMA 与 FC2 一致。固定 batch=8、stride=24、MSE。
5. 严格验证：本地 CPU 模型/指标测试，以及服务器启动前测试；每个任务完成后
   核查 checkpoint、预测数组及缓存指纹。技术失败和“数值未接近”分开记载。
6. 再汇总：新结果同样双口径报告全部 88 个论文表格单元（2 时长 × 11 个序列 ×
   4 指标），另报物理总需求 MAE。保留预测原数组的结果包支持独立重算，不含
   大 checkpoint；checkpoint 仍保留在服务器。

归一化和优化器的 2×2 组合是对未公开细节的预先限定敏感性检查，不是四套都
被论文指定。batch=8、CAM 宽度 16/16/1、per_day_vectors 的张量解释仍是重建
假设，不能声称已取得作者原始实现。原文 Fig.5 训练 100 轮与 S3 的 best_epoch
选择过程也未完整公开；本轮固定在公布的 best_epoch，不使用测试表选择轮数。

## 使用

运行前通过 `stop_que_queue.py --execute` 停止经身份确认的旧 targeted 队列。
该工具默认是 dry-run；只读检查可先不加 `--execute`。PID/cwd/脚本/用户或命名
空间无法核实时拒绝停止，不能退化成按 GPU 或 python 名称批量杀进程。

```bash
python scripts/train/run_que_protocol_audit.py --dry-run
nohup bash scripts/train/run_que_protocol_audit_gpu6.sh \
  > logs/que_protocol_audit_launcher.log 2>&1 &
echo $! > logs/que_protocol_audit_launcher.pid
```

默认只使用物理 GPU 6，一次一个训练任务。旧实验结果保持不变。队列允许同配置
断点重启；更改代码或数据后使用新 run tag，避免混用不同版本的结果。

优先查看 `audit_new/closeness_by_source.tsv`：同一来源、同一口径分别给出
`total8_passed`、`dma80_passed` 和 `all88_passed`。`paper_gaps.tsv` 保存逐单元
差距；`audit_existing` 为历史结果重算，不代表新增了多种子训练。

若 CPU 审计、启动测试、来源检查或显卡占用检查失败，先修复该证据链问题，不
应把退出误认为实验已完成。`formal_protocol` 仍是兼容性字段，仅表示部分训练
条件通过；真正的复现仍需公开的算法、数据和评价口径一致，不能由该布尔值认证。

  其公开 fullTextXML 镜像核对，未获取作者训练代码。
- 用户附件 `1-s2.0-S2589914724000598-mmc1 (9).docx`，S1、S3-1/2/3。
- 用户历史 87 任务汇总及 selected-joint 原始预测提供本地真值方差/指标证据。

“八个总体指标接近”不等于“所有 DMA 已接近”。新审计同时保留总指标和 DMA
逐项差距；未达标明确报告。不得对预测人工加噪、缩放、混合 checkpoint、挑选
每个指标最接近的不同实验，或把对测试表的拟合包装成独立复现。
