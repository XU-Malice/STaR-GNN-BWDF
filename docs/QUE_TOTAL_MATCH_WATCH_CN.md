# 在现有训练旁监测总体指标

本工具按六个模型各自的八项总体指标寻找数值接近论文的完整配置。每个模型同时比较 24 h、168 h 的 MAE、MAPE、RMSE、NSE，合计 48 项。分 DMA 指标的接近程度不参与排序或停止条件，各模型允许使用不同超参数，固定一个 seed。

默认接近标准为三项误差指标与论文的相对差不超过 5%，NSE 绝对差不超过 0.01，较高和较低都计入偏差。这是本项目预设的数值比较标准，不是论文作者规定的复现验收标准。

## 保持活动训练工作区不变

正在运行的综合队列会核对 `src/`、`scripts/`、`configs/`、`tests/` 和数据的内容指纹。直接在该工作区合并新代码或添加监测脚本，会使队列的源码检查不通过。

安装采用 `git fetch` 获取工具提交，再用 `git archive` 导出三个 Python 文件到项目之外的 `~/projects/que_total_watch_tools/<工具提交>/`。安装脚本由 `git show` 通过标准输入执行，**不进行 merge、checkout、pull 或环境重装**。活动训练继续使用原来的源码。

在项目目录中获取提供的完整工具提交后执行：

```bash
git show "$tools_commit:scripts/reproduce/install_que_total_watch.sh" | bash -s -- "$tools_commit"
```

应在启用 `set -e -o pipefail` 的子 shell 中执行完整安装命令。`tools_commit` 必须是提供的完整 40 位提交号。安装器自动找到 `bwdf311` 的 Python，先核验已有结果与冻结的源码，再后台启动监测。默认结果目录为 `results/que_comprehensive_reconstruction_shared_20260908`，队列 PID 记录为 `logs/que_shared_gpu7_launcher.pid`。

安装使用标准 Python、NumPy、PyYAML，监测不训练网络，不反序列化 `.pt` 权重，不占用 GPU。可以用 `QUE_WATCH_PYTHON` 指定已有 Python 可执行文件。重复启动受到独占锁保护。

某些 Python 构建没有暴露 `os.pidfd_open` 或 `signal.pidfd_send_signal`，不能仅凭此认定服务器内核不支持 pidfd。外部工具优先使用 Python 接口；缺少接口时使用系统 C 库导出的同名 pidfd 接口，仍通过进程文件描述符绑定身份和请求退出，不改用普通 PID 信号。接口实际不可用时，状态会明确显示“自动停止不可用”，继续每分钟扫描并在全部达标后保存结果。进程身份、权限或命名空间不符仍拒绝绑定。`--watch` 不带 `--stop-on-success` 时完全不依赖进程控制接口。

后台启动失败时，`--once` 预检已经生成的表仍是最后一次成功扫描的快照，并不表示结果归零；后台恢复前该表不会自动刷新。修复版将扫描前失败显示为“本次监测尚未完成结果扫描”，避免错误显示 `0/6`。

## 判定与停止顺序

1. 每 60 秒扫描全部已成功完成的候选。对每个模型按八项总体指标中的最大容差比排序，再以均值打破并列。它能发现平均差距榜单可能漏掉的八项同时接近的候选。
2. 常规进度表来自已保存指标，是初步判定。每个模型使用同一个完整候选计算全部八项，不能分别挑选不同预测长度或不同指标的最优值。阶段 D 已保存的独立 GRU/LSTM 网络组合也按总体指标比较。
3. 六个模型初步满足全部 48 项时，重新检查冻结的数据与源码、共同预测起点和真值、完整训练配置、权重文件哈希、原始预测、复用来源及两种预测长度的一致性，并从原始预测重新计算指标。
4. 所有检查通过后，先复制选中的权重、配置、预测、来源证明和源码快照，写入文件哈希清单，再生成含权重的结果包。
5. 使用 `--stop-on-success` 启动时，仅向启动监测时已核验身份的 Python 综合队列发送一次 `SIGTERM`。队列原有处理程序负责停止自己的训练子进程并保存日志。监测不终止其他用户进程，不按 GPU 批量终止进程，也不使用旧 Bash 队列的停止脚本。

停止请求可能中止当时尚未完成的一个搜索候选。选中并保存的达标配置均来自已经完成的结果，保存完成后才发出停止请求。

没有找到六个模型全部满足条件时，训练按原来的 B/C/D 计划继续。监测不改变现有队列的自适应候选生成规则，旧规则仍可能使用分 DMA 差距；监测的最终排序和停止判定只看总体指标。监测不保证有限搜索一定能找到全部达标的组合。

## 查看状态与结果

默认监测输出目录为 `results/que_total_match_watch_20260909`，包含：

| 文件 | 用途 |
|---|---|
| `watch_status.json` | 监测状态、各模型最接近配置、达标数、验证阶段、绑定队列身份与结果包位置 |
| `current_table.md` | 六个模型当前总体达标项数、最大误差相对差、NSE 最大绝对差 |
| `total_comparison.tsv` | 当前选中配置的 48 项实际值、论文值和差值 |
| `accepted_*.tar.gz` | 全部总体指标核验通过后生成的含权重结果包 |
| `accepted_*.tar.gz.sha256` | 结果包校验值 |

快速查看：

```bash
cat ~/projects/STaR-GNN-BWDF/results/que_total_match_watch_20260909/current_table.md
tail -n 20 ~/projects/STaR-GNN-BWDF/logs/que_total_match_watch_launcher.log
```

也可以直接运行外部工具的 `watch_que_total_match.py --status`，无需 GPU。

`matched_and_queue_stopped` 表示总体指标已核验、结果已保存，且绑定队列已退出。原训练队列可能显示 `interrupted`，对应监测发出的正常停止请求，应与监测结果包共同判断。

`matched_stop_requested_cleanup_pending` 表示停止请求已发出，但队列仍在清理或打包；监测不会强制升级终止措施。`observer_failed` 表示监测验证或运行出错，错误会保留；未完成验证和保存时不会请求停止训练。

结果中的“数值接近已核验”只对应这 48 项总体指标。参数选择使用了论文公开测试表作为目标，报告保留这一事实，不声称恢复了作者未公开的实现，也不把分 DMA 结果自动标记为接近。
